# Subagent

サブエージェントは、作業の分離、独立した意見の収集、メインコンテキストの保全に用いる。メインエージェントは依頼全体の方針、委譲範囲、結果の統合、最終検証を担う。サブエージェントは指定された範囲を完遂し、結果と根拠を返す。

## 委譲先の選択

委譲先は次の優先順位で選ぶ。

1. ユーザーの明示指定
2. 呼び出し元 Skill の指定
3. 適用されている共通・環境別指示
4. 利用可能な委譲先からの fallback

上位で選ばれた委譲先が利用可能な限り、別の委譲先へ暗黙に切り替えない。fallback は、委譲先が未導入、利用不能、必要な能力を持たない、または必要な許可を求めても得られない場合に限る。追加の許可の要求や初回の実行失敗のみを fallback の理由とせず、原因を確認した上で、その原因に対応する再試行を行う。委譲元自身を委譲先に選ばない。

各サブエージェントの利用方法は、次の各文書を参照のこと。

- [Claude Code の利用方法](references/claude-code.md)
- [Codex の利用方法](references/codex.md)
- [agy の利用方法](references/agy.md)

## 委譲範囲

- 独立して切り出せる調査、情報抽出、比較、整理は、規模にかかわらず原則として委譲する
- 方向性が決まった編集と、独立した意見を得る相談も主な委譲対象とする
- 前後の判断と密結合している作業や、委譲のために同程度の文脈を再構築する必要がある作業は、メインエージェントが実行してよい
- 並列化は、対象ファイルまたは判断範囲が独立している場合に限る。同じ成果物を複数のサブエージェントへ同時に編集させない
- 委譲は一階層に限定し、サブエージェントから別のサブエージェントへ再委譲させない。agy は例外とし、内部での入れ子を制限しない
- 再委譲の禁止は、ツール制限を設定できる配布先では定義側で設定し、設定できない配布先ではプロンプトに禁止を明記する

## 委譲プロンプト

委譲先が会話履歴や暗黙の前提を持たなくても完遂できる、自己完結したプロンプトを渡す。次の情報から、作業に必要なものを含める。

- 目的と期待する成果
- 対象のファイル、ディレクトリ、情報源
- 読み取り、編集、外部アクセスなどの許可範囲
- 守るべき設計判断、規約、禁止事項
- 完了条件と検証方法
- 根拠、差分、未解決事項など、返答に必要な情報

調査、編集、または判断を依頼した場合は、開始報告や承認要求だけで終了せず、許可された範囲で作業を完遂して結果を返すよう明記する。追加権限や依頼範囲の拡大が必要になった場合は、実行せず必要事項を報告させる。

CLI へファイルからプロンプトを渡す場合は、内容が空でないことを確認してから起動する。独立した依頼には新しいセッションを用いる。過去の会話が作業の前提となる場合に限り既存セッションを再開し、引き継ぐ文脈を明示する。

## 一時ファイル

委譲用のプロンプト、調査メモ、中間出力などの一時ファイルは、実行環境の一時領域の下に委譲単位のディレクトリを作成して配置する。プロジェクトの成果物として残す必要があるものだけを作業ツリーへ置く。委譲完了後、以後の検証や再利用に不要な一時ファイルはメインエージェントが削除する。失敗解析や継続作業に必要な場合は、完了まで保持してよい。

## 権限

依頼の完遂に必要な権限は与えてよい。読み取りで済む作業では不要な編集や外部状態の変更を避け、副作用のある操作は目的に必要な場合だけ行わせる。

## タイムアウト

委譲先の起動手段がタイムアウトまたは待機時間の指定を受け付ける場合、値は想定される所要時間の 3 倍以上とする。所要時間の想定が難しい場合は、既定値として 10 分を指定する。組み込みのサブエージェント起動、CLI の実行、CLI をラップするコマンドの待機時間設定など、指定手段を問わずこの基準を適用する。タスクを委譲して完了を待つときは、完了通知や完了待機の仕組みを優先して利用する。状態を確認する間隔は最低 1 分とし、複雑な依頼の場合は 5〜10 分を目安とする。指定方法は各サブエージェントの利用方法を参照のこと。

## 調査と根拠

調査対象を具体的に列挙し、実際に開いたファイル、ページ、URL と各対象から得た事実を報告させる。提案だけを返す余地を残さず、重要な結論には一次情報またはリポジトリ上の根拠を要求する。

取得した引用、ページ名と ID、ファイルの存在など、重要な根拠はメインエージェントが再確認する。複数の情報源が食い違う場合は、どの情報源を優先するかを確認してから結論を統合する。

## 編集と検証

Git 管理下の対象を編集させる場合は、委譲先に作業前後の `git status` と差分を確認させる。既存の変更と区別し、依頼外の変更を行わせない。Git 管理外では、バックアップ、隔離環境、dry-run など、対象に適した差分確認または復元方法を定める。

サブエージェントの完了報告だけで成果を確定しない。メインエージェントが、参照した根拠、実際の差分、生成物、検証結果を必要な範囲で確認する。文書やコードを生成させた場合は、重複、既存の配置規則や設計判断との不一致、調査対象間の食い違いも確認する。

## 失敗時

想定外の失敗では、エラー、実行環境、パス、権限、前提を確認して原因を絞り込む。同じ原因のまま別の手段を繰り返さず、原因に対応した変更を加えて最大二回まで再試行する。解決しない場合、または必要な権限が依頼範囲を超える場合は、確認した事実、原因の仮説、未完了の作業を報告して停止する。
