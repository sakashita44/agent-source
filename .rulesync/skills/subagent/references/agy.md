# agy の利用方法

`agy` は比較的安価に非対話実行できるため、小規模な調査を含む独立した作業の委譲に積極的に用いる。利用できるコマンド、モデル、オプションは、実行環境の `agy --help` と `agy models` で確認のこと。

## 非対話実行

`agy -p` に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- モデル: ユーザーの指示があればそれに従う。指示がなければ、`agy models` が表示する候補のうち最新世代を選び、同世代に複数のティアがある場合は上位のティアを選ぶ
- 推論強度: 最上位を用いる。強度がモデル ID に含まれる場合は、最上位の強度を含む ID を選ぶ
- タイムアウト: `--print-timeout` には `10m`、`1h` のような単位付きの時間を指定する。既定の時間設定では広範なリポジトリ調査や MCP を伴う調査で不足する場合があるため、[subagent スキルのタイムアウト基準](../SKILL.md)に従って値を決める
- 出力形式: ユースケースを問わず `--output-format json` とする。権限拒否を検出できる形式は JSON 出力に限られる。構造を保証する必要がある場合は `--json-schema` を併用する

## ユースケース別の起動方法

agy のモデルには起動時の cwd が伝わらない。相対パスや「現在のディレクトリ」で対象を示すと、agy は自身の scratch ディレクトリ（`~/.gemini/antigravity-cli/scratch`）などを作業場所と推測し、そこへ書き込んだ結果を完了として報告する。プロンプトでは、読み取りと書き込みの対象を必ず絶対パスで示す。

cwd と `--add-dir` は、agy が書き込みを承認する範囲を定める。

| ユースケース | cwd | 追加するオプション | プロンプトで示すこと |
| --- | --- | --- | --- |
| 情報を渡すだけの相談、比較、整理 | 委譲単位の一時ディレクトリ | なし | 判断に必要な情報のすべてと、その情報だけで答えること |
| コードベースの読み取り調査 | 調査対象のリポジトリのルート | なし | 読む対象の絶対パス |
| Web 調査 | 委譲単位の一時ディレクトリ。リポジトリも読む場合はそのルート | なし | 読む URL、サイト、検索範囲 |
| cwd 内の編集 | 編集対象の作業ツリーのルート | `--mode accept-edits` | 編集対象の絶対パスと、agy 自身が対象を直接編集すること |
| cwd 外を含む編集 | 主な編集対象の作業ツリーのルート | `--mode accept-edits`、追加の対象ルートごとの `--add-dir` | 各ルートの絶対パスと、ルートごとに許可するファイルと操作 |

- `--mode accept-edits` を付けない場合、cwd 内への書き込みも拒否される
- `--mode accept-edits` が承認する範囲は、cwd と `--add-dir` で加えたディレクトリに限られる。`--add-dir` には、編集に必要な最小のディレクトリを指定する
- agy の scratch や `%TEMP%` 配下に作られたファイルは、成果物として扱わない
- `--sandbox` は付けない

## コマンドの扱い

agy は、`--mode accept-edits` を指定してもシェルコマンドの実行を承認しない。コマンドが一度でも拒否されると、その時点でターンが終了し、残りの調査、編集、報告も行われない。

委譲プロンプトでは、シェルコマンドの実行を禁じ、ファイルの読み取りや編集、Web の読み取りに用いるツールだけで作業するよう指示する。対象を「探して」「確認して」とだけ依頼すると、agy がコマンドで探索を試みる場合がある。探索の範囲を絶対パスで示し、使うツールの種類も指定する。

コマンドの結果が必要な作業は、起動元と agy の作業に分ける。

- 起動元が事前に実行する: Issue の本文、Git の履歴や状態など、コマンドによる情報の取得。結果はプロンプトの本文、または絶対パスで示した一時ファイルで渡す。コマンド名をプロンプトに書く場合は、実行の指示と誤読されないよう、参考情報であることを示す
- 起動元が事後に実行する: 差分の確認、テスト、lint、ビルド。失敗した場合は、その出力を渡して修正だけを再度委譲する

読み取り専用のコマンドは、該当するコマンドを許可する規則を利用者が agy の設定（`~/.gemini/antigravity-cli/settings.json` の `permissions.allow`）にあらかじめ定めている場合に限り、実行させてよい。この場合は、実行させるコマンドと引数をプロンプトに明示する。起動元は agy の設定へ規則を追加または変更しない。

`--dangerously-skip-permissions` は、agy 内部の全ツールの権限確認を省略する。委譲プロンプトによる操作の限定は、ツール権限による制限の代わりにはならない。外部で隔離された環境と、このオプションに対するユーザーの明示的な許可がある場合に限って指定する。指定する場合も、委譲プロンプトで対象と目的を限定し、不要なファイルの作成、編集、削除や、Git 操作、外部状態の変更を禁じる。

## PowerShell での起動構文

起動コマンドは、`agy` から始まる 1 文として記述する。起動元の許可ルールは PowerShell の文を 1 文ずつ判定するため、変数への代入や空ファイルの確認を同じコマンドに含めると、それらの文が許可ルールに一致せず承認を求められる。そのため、プロンプトファイルが空でないことの確認は、起動前に別の手順で行う。

次のコード例は読み取り調査の説明用であり、`<prompt-file>`、`<output-file>`、`<選んだモデルID>` を実際の値に置き換えて実行する。編集を委譲する場合は、[ユースケース別の起動方法](#ユースケース別の起動方法)に従ってオプションを追加する。

```powershell
agy -p (Get-Content '<prompt-file>' -Raw) --model '<選んだモデルID>' --effort high --print-timeout 20m --output-format json > '<output-file>'
```

コマンド名 `agy` を解決できない環境では、解決した `agy.exe` の絶対パスを文字列のまま呼び出し演算子 `&` で起動する（`& 'C:\...\agy.exe' -p (Get-Content '<prompt-file>' -Raw) ...`）。実行ファイルのパスを変数に格納して起動すると、起動元の許可ルールに一致しない場合がある。実行環境に配布されたルールが解決手順を定めている場合は、その手順に従う。

並列に委譲する際、起動元のツールが並列呼び出しに対応している場合は、`agy` の直接起動を委譲ごとに独立したツール呼び出しとして実行する。`Start-Job` やラッパースクリプトを経由させると、起動元の許可ルールに一致せず拒否される場合がある。並列呼び出しが使えない場合は逐次実行する。

## 実行時権限の指定

リポジトリなどの情報を送る場合は、送信先が Google Antigravity であること、対象パス、許可する操作を委譲プロンプトと実行時の説明に明記する。ユーザーまたはプロジェクトの指示が読み取り委譲を許可している範囲では、同じ許可を重ねて確認しない。許可されたパスを超える場合、秘密情報を含む可能性がある場合、または編集や外部状態の変更が必要な場合は、実行前にユーザーへ確認する。

起動元の分類器、sandbox、権限設定が `agy` の起動を拒否した場合は、拒否されたコマンドと理由を確認する。ラッパーによって許可ルールから外れた場合は直接起動に戻し、`--dangerously-skip-permissions` が拒否の原因であれば除外して再試行する。起動自体に承認が必要なら、起動元の承認手順で必要な範囲の承認を要求する。設定ファイルの書き換えや権限確認の無効化によって迂回しない。拒否のみを理由に別の委譲先へ切り替えず、再試行後も必要な権限を得られない場合は、拒否された操作と必要な権限を示してユーザーへ確認する。

agy の実行中に Windows の UAC が管理者権限を求めた場合は、キャンセルし、その委譲を失敗として扱う。原因となったオプションを確認し、ユーザーへ報告する。

## 権限拒否と完了の判定

ツールの呼び出しが拒否されても、agy は終了コード 0 で終了し、JSON 出力の `status` は `SUCCESS` になる。終了コードと `status` は成功の根拠にしない。

JSON として解析できない出力は、成功として扱わない。JSON 出力の `denied_actions` に項目がある場合は、権限拒否による失敗として扱う。拒否がなければ、`denied_actions` は出力に含まれない。拒否された `action` が `write_file` の場合は、cwd、`--mode accept-edits`、`--add-dir`、プロンプトの絶対パスを見直して再試行する。`command` の場合は、[コマンドの扱い](#コマンドの扱い)に従って、コマンドを起動元の作業へ分ける。

`denied_actions` に項目がない場合でも、agy の完了報告だけで成果を確定しない。編集を委譲した場合は、指定した絶対パスの差分を起動元が確認する。調査を委譲した場合は、実際に開いたファイルや URL と、そこから得られた事実が報告されていることを確認する。

テキスト出力は処理が完了するまで表示されない場合があるため、実行中に出力が空であることだけを理由に失敗と判断しない。終了後に応答が空、極端に短い、または調査記録を欠く場合は、`denied_actions`、ログ、タイムアウトを確認のこと。原因が分からないまま成功とみなしたり、別の委譲先へ切り替えたりしない。

## 再委譲の扱い

agy の内部では、サブエージェントからの再委譲を禁止せず、入れ子の深さを 1 に制限する設定も行わない。委譲した作業の分解は agy 側の処理に委ねる。

入れ子が深くなると並列度と消費が増加するため、想定より所要時間や出力量が大きい場合は、依頼の範囲を分割して個別に委譲する。

## 文章書き換えの指示

文章の書き換えを依頼する場合、「意味と指示の強さを変えない」という一般的な指示だけでは、禁止されている文末形式、表記（半角スペース、句読点、数の表記）、使い分けられている用語の区別が損なわれることがある。保護したい対象はプロンプトに具体的に列挙する。
