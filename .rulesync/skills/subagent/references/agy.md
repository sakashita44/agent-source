# agy の利用方法

`agy` は比較的安価に非対話実行できるため、小さな調査を含む独立した作業の委譲に積極的に用いる。利用できるコマンド、モデル、オプションは、実行環境の `agy --help` と `agy models` で確認のこと。

## 非対話実行

`agy -p` に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- モデルは、ユーザーの指示があればそれに従う。指示がなければ、`agy models` が表示する候補のうち最も新しい世代のものを選ぶ
- 同じ世代に複数のティアがある場合は、上位のティアを選ぶ
- 推論強度は最上位を用いる。強度がモデル ID に含まれる場合は、最上位の強度を含む ID を選ぶ
- `--print-timeout` には `10m`、`1h` のような単位付きの時間を指定する。既定の時間設定では広範なリポジトリ調査や MCP を伴う調査で不足する場合があるため、[subagent スキルのタイムアウト基準](../SKILL.md)に従って値を決める
- ワークスペース外の対象が必要な場合は、追加ディレクトリを明示する

`--output-format json` または `stream-json` は、結果を機械処理する場合や進捗イベントを取得する場合に用いる。構造を保証する必要がある場合は `--json-schema` を併用する。

非対話実行（`-p`）でも、agy が内部でサブエージェントやバックグラウンドタスクを起動し、対象を編集しないまま終了することがある。編集を依頼する場合は、サブエージェントを起動せず、対象ファイルを直接読み書きするようプロンプトで指示する。

### PowerShell での起動構文

実行ファイルとプロンプトを変数に読み込み、プロンプトが空でないことを確認して呼び出し演算子 `&` で起動する。次のコード例は読み取り専用調査の説明用であり、`<agy-executable>`、`<prompt-file>`、`<選んだモデルID>` を実際の値に置き換えて実行する。

`<agy-executable>` には、コマンド名で解決できる環境では `agy` を、解決できない環境では解決した `agy.exe` の絶対パスを指定する。実行環境に配布されたルールが解決手順を定めている場合は、その手順に従う。

```powershell
$agy = '<agy-executable>'
$prompt = Get-Content '<prompt-file>' -Raw
if ([string]::IsNullOrWhiteSpace($prompt)) { throw 'prompt is empty' }
& $agy -p $prompt --model '<選んだモデルID>' --effort high --print-timeout 20m --sandbox
```

並列に委譲する際、起動元のツールが並列呼び出しに対応している場合は、上記の直接起動を委譲ごとに独立したツール呼び出しとして実行する。`Start-Job` やラッパースクリプトで包むと、起動元の許可ルールに一致せず拒否される場合がある。並列呼び出しが使えない場合は逐次実行する。

## 実行時権限の指定

headless 実行では権限確認に対話応答できない。必要な権限が許可されていない場合、ツールの呼び出しが拒否されても標準出力が空のまま終了することがある。出力だけで失敗原因を決めず、権限拒否を確認する。

`--dangerously-skip-permissions` は、agy 内部の全ツールの権限確認を省略する。委譲プロンプトによる操作の限定は、ツール権限の制限に代わらない。外部で隔離された環境と、このオプションに対するユーザーの明示的な許可がある場合に限って指定する。指定する場合も、委譲プロンプトで対象と目的を限定し、不要なファイルの作成、編集、削除、Git 操作、外部状態の変更を禁じる。

リポジトリなどの情報を送る場合は、送信先が Google Antigravity であること、対象 path、許可する操作を委譲プロンプトと実行時の説明へ明記する。ユーザーまたはプロジェクトの指示が読み取り委譲を許可している範囲では、同じ許可を重ねて確認しない。許可された path を超える場合、秘密情報を含む可能性がある場合、または編集や外部状態の変更が必要な場合は、実行前に確認する。

起動元の分類器、sandbox、権限設定が `agy` の起動を拒否した場合は、拒否されたコマンドと理由を確認する。ラッパーにより許可ルールから外れた場合は直接起動へ戻し、`--dangerously-skip-permissions` が拒否の原因なら外して再試行する。起動自体に承認が必要なら、起動元の承認手順で必要な範囲を要求する。設定ファイルの書き換えや権限確認の無効化で迂回しない。拒否のみを理由に別の委譲先へ切り替えず、再試行後も必要な権限を得られない場合は、拒否された操作と必要な権限を示してユーザーへ確認する。

Web 調査の出力に `read_url permission` または `auto-denied` が現れた場合は、調査結果なしとして扱い、権限拒否を原因として報告する。

## 出力の確認

テキスト出力は処理が完了するまで表示されない場合がある。実行中に出力が空であることのみをもって失敗と判断しない。終了後に出力が空、極端に短い、または調査記録を欠く場合は、標準エラー出力、ログ、権限拒否、タイムアウトを確認のこと。原因が分からないまま成功扱いにしたり、別の委譲先へ切り替えたりしない。

## 再委譲の扱い

agy の内部では、サブエージェントからの再委譲を禁止しない。入れ子の深さを 1 に制限する設定も行わない。委譲した作業の分解は agy 側の処理に委ねる。

入れ子が深くなると並列度と消費が増加する。想定より所要時間または出力量が大きい場合は、依頼の範囲を分割して個別に委譲する。

## 文章書き換えの指示

文章の書き換えを依頼する場合、「意味と指示の強さを変えない」という一般的な指示だけでは、禁止の文末形、表記（半角スペース、句読点、数の表記）、使い分けられている用語の区別が崩れることがある。保護したい対象はプロンプトで具体的に列挙する。
