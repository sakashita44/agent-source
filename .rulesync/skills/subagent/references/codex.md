# Codexの利用方法

Codexは、非対話実行によって独立した調査、判断、編集を委譲するために用いる。利用できるコマンドとオプションは、実行環境の`codex exec --help`で確認する。

## 非対話実行

`codex exec`に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- 設計相談、実装提案、アーキテクチャ評価には、利用可能なモデルから高い推論能力を持つクラスを選ぶ。モデル名と設定方法は`codex exec --help`と実行環境の設定で確認する
- 作業ディレクトリと追加ディレクトリは、対象へアクセスできる最小範囲に限定する
- sandboxと承認方針は、必要な読み取り、編集、コマンド実行に合わせて選ぶ
- 機械処理や長い出力の確実な回収が必要な場合は、利用可能な構造化出力または出力ファイルを用いる

### PowerShell例

stdinの扱いはシェルとCLIの組合せに左右されるため、単一プロンプトを変数へ読み込み、空でないことを確認して引数として渡す。

```powershell
$prompt = Get-Content '<prompt-file>' -Raw
if ([string]::IsNullOrWhiteSpace($prompt)) { throw 'prompt is empty' }
codex exec --sandbox workspace-write --ephemeral -C '<workspace>' $prompt
```

## サンドボックスと承認

- `read-only`はファイル編集だけでなく、PowerShellの一部機能や子プロセスを制限する場合がある。調査コマンドが失敗した場合は、対象の不具合と判断する前にサンドボックス由来か確認する
- `workspace-write`は作業領域への書き込みを許可する。読み取りだけを依頼する場合もこのモードが必要なら、プロンプトで編集を禁止し、実行前後のGit状態を確認する
- 追加ディレクトリは書き込み可能領域として扱われる場合がある。必要な対象だけを指定する
- sandboxと承認を無効にするオプションは、外側で隔離され、対象と副作用を限定できる場合に限って用いる
- Gitリポジトリの信頼判定を省略するオプションは、対象が意図したディレクトリであることを確認してから用いる

すべてのシェル実行が起動直後に失敗する場合は、権限を緩和する前に、起動した`codex`の実体と同梱されたsandbox helperが同じ配布物に属するか確認する。複数のインストールがある環境では、`Get-Command codex`と`codex --version`で実体を識別する。

## 出力とセッション

最終応答を確実に回収する場合は出力ファイルを指定し、イベントを処理する場合はJSONL出力を用いる。応答形式を機械的に検証する必要がある場合は出力スキーマを指定する。

セッションを保存しない場合は`--ephemeral`を用いる。既存セッションを再開する場合は、`resume`または`fork`で元の調査文脈を引き継ぐか分岐するかを選ぶ。
