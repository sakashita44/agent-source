# Codex の利用方法

Codex は、非対話実行によって独立した調査、判断、編集を委譲するために用いる。利用できるコマンドとオプションは、実行環境の `codex exec --help` で確認する。

## 非対話実行

`codex exec` に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- 設計相談、実装提案、アーキテクチャ評価には、利用可能なモデルの中から高い推論能力を持つクラスを選択する。モデル名と設定方法は `codex exec --help` および実行環境の設定で確認する
- 作業ディレクトリと追加ディレクトリは、対象へアクセスできる最小限の範囲に限定する
- sandbox と承認方針は、必要な読み取り、編集、コマンド実行に合わせて選択する
- 機械処理や長い出力の確実な回収が必要な場合は、利用可能な構造化出力または出力ファイルを用いる
- 起動元がタイムアウトの指定を受け付ける場合（Bash ツールの `timeout` パラメータなど）は、[SKILL.md](../SKILL.md) のタイムアウト基準に従う

### PowerShell 例

stdin の扱いはシェルと CLI の組み合わせに左右されるため、単一プロンプトを変数に読み込み、空でないことを確認して引数として渡す。

```powershell
$prompt = Get-Content '<prompt-file>' -Raw
if ([string]::IsNullOrWhiteSpace($prompt)) { throw 'prompt is empty' }
codex exec --sandbox workspace-write --ephemeral -C '<workspace>' $prompt
```

## サンドボックスと承認

- `read-only` はファイル編集だけでなく、PowerShell の一部機能や子プロセスの実行を制限する場合がある。調査コマンドが失敗した場合は、対象の不具合と判断する前に、サンドボックスに起因するものかを確認する
- `workspace-write` は作業領域への書き込みを許可する。読み取りのみを依頼する場合であってもこのモードが必要なときは、プロンプトで編集を禁止し、実行前後の Git の状態を確認する
- 追加ディレクトリは書き込み可能な領域として扱われる場合があるため、必要な対象のみを指定する
- sandbox と承認を無効にするオプションは、外部で隔離されており、対象と副作用を限定できる場合に限って用いる
- Git リポジトリの信頼判定を省略するオプションは、対象が意図したディレクトリであることを確認したうえで用いる

すべてのシェル実行が起動直後に失敗する場合は、権限を緩和する前に、起動した `codex` の実体と同梱された sandbox helper が同一の配布物に属しているかを確認する。複数のインストールが存在する環境では、`Get-Command codex` と `codex --version` で実体を識別する。

## 出力とセッション

最終応答を確実に回収する場合は出力ファイルを指定し、イベントを処理する場合は JSONL 出力を用いる。応答形式を機械的に検証する必要がある場合は出力スキーマを指定する。

セッションを保存しない場合は `--ephemeral` を用いる。既存セッションを再開する場合は、`resume` または `fork` で元の調査文脈を引き継ぐか分岐させるかを選択する。
