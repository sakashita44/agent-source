# Claude Code の利用方法

Claude Code は、非対話実行によって独立した調査、判断、編集を委譲するために用いる。利用できるコマンドとオプションは、実行環境の `claude --help` で確認する。

## 非対話実行

`claude -p` に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- 設計相談、実装提案、アーキテクチャ評価には、原則として Opus 級のモデルと高い推論強度を用いる。実行環境が提供する最新の同等クラスを選ぶ
- 対象が作業ディレクトリの外にある場合は、必要なディレクトリだけを追加する
- 読み取り、編集、コマンド実行の権限は、依頼に必要な範囲に限定する
- 機械処理や長い出力の確実な回収が必要な場合は、利用可能な構造化出力を選択する
- 起動元がタイムアウトの指定を受け付ける場合（Bash ツールの `timeout` パラメータなど）は、[SKILL.md](../SKILL.md) のタイムアウト基準に従う

### PowerShell 例

プロンプトを変数に読み込み、空でないことを確認して引数として渡す。

```powershell
$prompt = Get-Content '<prompt-file>' -Raw
if ([string]::IsNullOrWhiteSpace($prompt)) { throw 'prompt is empty' }
claude -p $prompt --model opus --effort high --output-format text
```

`--model opus` のような能力帯を表す別名が利用できる場合は、固定された世代名より優先する。利用できる推論強度は `claude --help` で確認する。

## 権限と実行モード

- 読み取り専用の相談では、編集を禁止するプロンプトに加え、`--permission-mode plan`、`--restricted`、許可・禁止ツールの指定などから、必要なツールを利用できる最小限の制約を選択する
- 編集を許可する場合は、許可するディレクトリとツールを限定する。`--dangerously-skip-permissions` は、外部で隔離された環境に限定して用いる
- `-p` ではワークスペースの信頼確認が表示されないため、信頼できるディレクトリでのみ実行する
- 非対話実行では不正な設定ファイルが対話なしで無視される場合がある。想定した MCP、Skill、hook、権限設定が必要な作業では、実際に読み込まれたことを成果報告またはデバッグ出力で確認する

## 出力とセッション

`--output-format json` または `stream-json` は、結果の機械処理や進捗取得に用いる。構造を保証する必要がある場合は `--json-schema` を併用する。費用の上限が必要な非対話実行では、利用可能な予算上限オプションを設定する。

セッションを保存しない場合は `--no-session-persistence` を用いる。既存セッションを再開する場合は、`--resume` または `--continue` に必要な識別情報を保持する。

## セッション内の委譲

Claude Code のセッション内では、委譲先の種別とモデルを起動時に指定する。種別は、読み取りのみで完結する探索と、編集や外部アクセスを伴う作業とで使い分ける。モデルは、判断の難易度と対象の規模に応じて選択する。定型的な走査に上位モデルを割り当てない。起動手段がタイムアウトまたは待機時間の指定を受け付ける場合は、[SKILL.md](../SKILL.md) のタイムアウト基準に従う。

サブエージェントの入れ子は、既定で 3 階層まで許可されている。一階層にとどめる場合は、委譲先に対して再委譲の禁止を明示するか、委譲を起動するツール自体を持たせない。

配布済みのサブエージェント定義を使用する場合は、ツールの制限と守るべき制約が定義側に含まれているため、プロンプトに再掲しない。定義に記載されていない対象、完了条件、報告内容のみを渡す。
