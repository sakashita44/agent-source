# Claude Codeの利用方法

Claude Codeは、非対話実行によって独立した調査、判断、編集を委譲するために用いる。利用できるコマンドとオプションは、実行環境の`claude --help`で確認する。

## 非対話実行

`claude -p`に、目的、対象、許可範囲、制約、完了条件、必要な報告を含む自己完結したプロンプトを渡す。

- 設計相談、実装提案、アーキテクチャ評価には、原則としてOpus級のモデルと高い推論強度を用いる。実行環境が提供する最新の同等クラスを選ぶ
- 対象が作業ディレクトリの外にある場合は、必要なディレクトリだけを追加する
- 読み取り、編集、コマンド実行の権限は、依頼に必要な範囲へ限定する
- 機械処理や長い出力の確実な回収が必要な場合は、利用可能な構造化出力を選ぶ

### PowerShell例

プロンプトを変数へ読み込み、空でないことを確認して引数として渡す。

```powershell
$prompt = Get-Content '<prompt-file>' -Raw
if ([string]::IsNullOrWhiteSpace($prompt)) { throw 'prompt is empty' }
claude -p $prompt --model opus --effort high --output-format text
```

`--model opus`のような能力帯を表す別名が利用できる場合は、固定された世代名より優先する。利用できる推論強度は`claude --help`で確認する。

## 権限と実行モード

- 読み取り専用の相談では、編集を禁止するプロンプトに加え、`--permission-mode plan`、`--restricted`、許可・禁止ツールの指定などから、必要なツールを利用できる最小の制約を選ぶ
- 編集を許可する場合は、許可するディレクトリとツールを限定する。`--dangerously-skip-permissions`は、外側で隔離された環境に限って用いる
- `-p`ではワークスペースの信頼確認が表示されないため、信頼できるディレクトリだけで実行する
- 非対話実行では不正な設定ファイルが対話なしで無視される場合がある。想定したMCP、Skill、hook、権限設定が必要な作業では、実際に読み込まれたことを成果報告またはデバッグ出力で確認する

## 出力とセッション

`--output-format json`または`stream-json`は、結果の機械処理や進捗取得に用いる。構造を保証する必要がある場合は`--json-schema`を併用する。費用の上限が必要な非対話実行では、利用可能な予算上限オプションを設定する。

セッションを保存しない場合は`--no-session-persistence`を用いる。既存セッションを再開する場合は、`--resume`または`--continue`に必要な識別情報を保持する。
