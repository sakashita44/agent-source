# Plan

実装計画を策定し、Issue へ分解する。縦スライスの判定、Issue の粒度、進行制御を扱う。

意図、決定、経路の層分けは `artifact-principles` を参照する。

## 適用境界

機能やマイルストーンの実装計画、ロードマップの策定や再構成、作業の Issue 分解、実装経路の見直しに用いる。1〜2 ファイルの自明な変更は、計画を立てずにそのまま実行する。確定済み計画の実行と、完成した文書の執筆は対象外とする。

要件、スコープ、成功基準が定まっておらず、意図や分解を仮定で埋めることになる段階では、`grill-me` の実行を提案し、判断を仰ぐ。

## 手順

1. 各段階で何をしたいのかを、型名、関数名、具体的な定数を使わずに言語化する
2. 意図、決定、経路を各層へ振り分ける。着手前に合意が必要な決定は、decision issue または ADR へ記載する
3. 縦スライスに分割する
4. 各スライスを自己完結した Issue にする
5. 純粋版を生成する
6. 計画を提示する

### 縦スライスの判定

コア機能を貫く最小の一本から切り出す。各スライスは次を満たす。

- 未完成の部分に依存せず、単独で成立する
- 単体で検証できる。確認方法は対象領域による
- 他のスライスと並行して進めても衝突しない

全体を一括で確定させず、次に着手する一歩の粒度で計画する。

### Issueの粒度

会話の文脈を持たない読み手が、前提を含めてそのまま着手できる粒度にする。ロードマップ Issue には依存関係の順序を記載する。

未確定事項は、対象と必要な判断が分かる形に局所化してから次の段階へ進む。未確定のまま経路を確定させない。

### 純粋版の生成

計画が固まったら、`purify-artifact` サブエージェントへ計画本文と元の要求のみを渡し、経緯に由来する記述を除いた版を受け取る。検討した却下案とその理由は渡さない。

decision issue を作成した後に実行する。順序を逆にすると、後から参照する価値のある判断理由が失われる。

## 判断が分かれた場合

複数の案を比較して判断が分かれた場合は、各案と判断が分かれる理由を示してユーザーへ確認する。自律的に決めきることを目的にしない。

## 制約

- スコアリングや重み付け式による優先順位付けを持ち込まない
- この Skill 独自の承認ゲートを設けない
- 計画の実行とコミットを行わない
