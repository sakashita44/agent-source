# Setup Project

プロジェクトの技術構成と既存規約に合わせ、開発設定を導入または提案する。[project-standards](https://github.com/sakashita44/project-standards)を参考にするが、対象リポジトリの指示、既存設定、利用ツールを優先する。

## プロジェクトの判定

対象リポジトリのルート、Git状態、主要言語、package manager、build・test・lintの仕組み、既存の設定ファイルとGitHub設定を確認する。空または初期構築中なら新規プロジェクト、運用中のコードや固有設定があるなら既存プロジェクトとして扱う。

`project-standards`のREADMEと、対象技術に関係するディレクトリだけを確認する。分類名へ機械的に当てはめず、対象リポジトリで実際に使う設定だけを選ぶ。

## 状態別の処理

### 新規プロジェクト

共通設定と対象技術の設定を開始点として導入する。`.gitattributes`、`.editorconfig`、ignore、formatter、linter、GitHub設定、project-levelのhookとCIから、対象に必要なものを選ぶ。テンプレートのplaceholderをプロジェクトの実値へ置換し、配置先やコマンドを対象ツールの仕様へ合わせる。

依存関係の導入やhookの有効化は、セットアップの完了に必要な範囲で実行する。外部リポジトリの作成、push、既存ファイルの破壊的な置換など、依頼から自明でない外部変更は別途確認する。

### 既存プロジェクト

既存設定を変更する前に、`project-standards`との差分を調べる。各提案について、対象ファイル、導入する意図、既存挙動への影響、競合する設定を示し、ユーザーの選択を待つ。設定一式の置換や、正本への継続同期は提案しない。

承認された変更だけを、既存の命名、配置、package manager、toolchainへ適応して実施する。既存のhook、CI、formatter、linterが同じ目的を担う場合は重複導入しない。

## エージェント指示ファイルの規約

リポジトリに置くエージェント向けの指示ファイルは、`AGENTS.md`を正本とし、ツール固有のファイルは`AGENTS.md`を参照するだけに留める。組み込みの初期化コマンドは他ツールの設定内容を自身のファイルへ取り込むため、正本が複数に分かれて内容が乖離する。参照で一本化すると、更新箇所が1つに定まる。

### ファイルの構成

#### 配置と参照

`AGENTS.md`をリポジトリルートへ置く。Claude Codeは`AGENTS.md`を読まないため、同じ階層の`CLAUDE.md`へ`@AGENTS.md`の1行だけを書き、import で取り込ませる。

symlinkは用いない。Windowsでの作成には管理者権限または開発者モードが要る。

import の記法はClaude Codeの機能である。Codexは指示ファイルをディレクトリ探索で集めて連結するだけで、他ファイルを取り込む記法を持たない。`AGENTS.md`へ書いた参照は、Claude Codeでは展開され、Codexでは文字列のまま残る。

#### ローカル限定の内容

個人の環境、資格情報の所在、検証用のURL、個人的な作業の好みは、共有する指示ファイルへ書かない。

置き場所は、リポジトリ内のローカル専用ファイルを既定とする。ルートへ1つ置いてgitignoreへ加え、`AGENTS.md`から参照する。対象のリポジトリで作業するときだけ読み込まれ、内容の所在がリポジトリ内で完結する。

ユーザー層（`~/.claude/`、`~/.codex/`など）へ置く案は、その層を生成元リポジトリから配布している場合には採らない。生成物を直接編集することになり、次回の生成で失われる。個人設定をユーザー層へ置く必要が生じた場合は、生成元リポジトリの入力を変更する。

ローカル専用ファイルを参照する場合、2つの制約を伴う。共有する`AGENTS.md`へ参照を書くと、そのファイルが配置されていない環境では参照先が存在しない。またCodexは参照を展開しないため、内容が届くのはClaude Codeに限られる。両方のエージェントへ個人設定を届ける必要がある場合は、各ツールが自身で探索するファイル名（Claude Codeの`CLAUDE.local.md`など）を用いる。

`AGENTS.override.md`は用いない。Codexは各ディレクトリで`AGENTS.override.md`、`AGENTS.md`の順に探索し、最初に見つかった1つだけを読む。同じ階層に両方を置くと共有側の`AGENTS.md`が読まれなくなる。`CLAUDE.local.md`は後に連結されるため挙動が異なり、同じ配置をすると共有ルールが失われる。

#### バージョン管理の方針

共有用の指示ファイルはコミットし、個人用のファイルは追跡しない。外部からのpull requestを受け入れるリポジトリでは、指示ファイルへの変更を通常のコードと同じレビュー対象として扱う。指示ファイルに書かれた内容はエージェントの動作を変えるため、レビューを経ない変更を取り込まない。

### 記述の設計

#### 記載内容の取捨

各行について「この記述を消すと、エージェントが誤った操作をするか」を問い、否なら書かない。

書く対象は、リポジトリ固有で、コードを読んでも判明しない事実に限る。非標準のビルド・テスト・lintコマンド、言語の既定と異なるコード規約、テストの癖、ブランチとPRの運用、必要な環境変数、非自明な制約が該当する。

書かない対象は、ファイルやコンポーネントの列挙、言語の標準的な慣習、一般的な開発上の助言、マニフェストファイルから自明なコマンドである。長い参考情報と変化が速い情報は、指示ファイルへ転記せず、参照の記法で対象ファイルを指す。

#### 分量の制約

指示ファイルは毎セッションのコンテキストを消費する。加えて、読み込み方がツールごとに異なる。

- Codex: ルートから作業ディレクトリへ向かって連結し、累積サイズが`project_doc_max_bytes`（既定32 KiB）に達した時点で以降を読まない
- Claude Code: 上位ディレクトリから連結し、同じ階層の`CLAUDE.local.md`を後に足す

いずれの読み込み方でも意図した内容が届くよう、全エージェントに共通して必要な内容だけを置き、短く保つ。

#### ツール固有の記述

ツール固有の記述は置かないことを既定とする。必要な場合に限り、Codex と Antigravity に関する内容を`AGENTS.md`へ、Claude Code に関する内容を`CLAUDE.md`の`@AGENTS.md`より下へ置く。

## 完了確認

- 未置換のplaceholderと一時ファイルが残っていないこと
- 設定ファイルの参照pathと実際の配置が一致すること
- `.gitattributes`とformatterの改行規則が矛盾しないこと
- 導入したコマンド、hook、CIが対象プロジェクトの依存関係と一致すること
- diffに依頼範囲外の変更や秘密情報が含まれないこと
- エージェント指示ファイルを扱った場合、正本が`AGENTS.md`の1つに定まり、個人用の内容が共有対象へ混入していないこと

新規プロジェクトでは実施内容と検証結果を報告する。既存プロジェクトでは、未承認の提案を実施済みの変更と区別して報告する。
