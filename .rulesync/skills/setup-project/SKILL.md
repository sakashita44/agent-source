# Setup Project

プロジェクトの技術構成と既存規約に合わせ、開発設定を導入または提案する。[project-standards](https://github.com/sakashita44/project-standards) を参考にするが、対象リポジトリの指示、既存設定、利用ツールを優先する。

## プロジェクトの判定

対象リポジトリのルート、Git の状態、主要言語、package manager、ビルド・テスト・lint の仕組み、既存の設定ファイルと GitHub 設定を確認する。空または初期構築中なら新規プロジェクト、運用中のコードや固有設定があるなら既存プロジェクトとして扱う。

`project-standards` の README と、対象技術に関係するディレクトリのみを確認する。分類名へ機械的に当てはめず、対象リポジトリで実際に使用する設定のみを選択する。

## 状態別の処理

### 新規プロジェクト

共通設定と対象技術の設定を開始点として導入する。`.gitattributes`、`.editorconfig`、ignore、formatter、linter、GitHub 設定、project-level の hook や CI から、対象に必要なものを選択する。テンプレートの placeholder をプロジェクトの実値へ置換し、配置先やコマンドを対象ツールの仕様に合わせる。

依存関係の導入や hook の有効化は、セットアップの完了に必要な範囲で実行する。外部リポジトリの作成、push、既存ファイルの破壊的な置換など、依頼内容から自明でない外部変更は事前に確認する。

### 既存プロジェクト

既存設定を変更する前に、`project-standards` との差分を調査する。各提案について、対象ファイル、導入する意図、既存の挙動への影響、競合する設定を示し、ユーザーの選択を待つ。設定一式の置換や、正本への継続的な同期は提案しない。

承認された変更のみを、既存の命名、配置、package manager、toolchain に合わせて適用する。既存の hook、CI、formatter、linter が同じ目的を担う場合は重複して導入しない。

## エージェント指示ファイルの規約

リポジトリに配置するエージェント向けの指示ファイルは、`AGENTS.md` を正本とし、ツール固有のファイルは `AGENTS.md` を参照するのみに留める。組み込みの初期化コマンドは他ツールの設定内容を自身のファイルへ取り込むため、正本が複数に分かれて内容が乖離する原因となる。参照によって一本化することで、更新箇所が 1 つに定まる。

### ファイルの構成

#### 配置と参照

`AGENTS.md` をリポジトリルートに配置する。Claude Code は `AGENTS.md` を読み込まないため、同一階層の `CLAUDE.md` に `@AGENTS.md` の 1 行のみを記述し、import で取り込ませる。

symlink は用いない。Windows での作成には管理者権限または開発者モードが必要となる。

import の記法は Claude Code の機能である。Codex は指示ファイルをディレクトリ探索で収集して連結するのみで、他ファイルを取り込む記法を持たない。`AGENTS.md` に記述した参照は、Claude Code では展開され、Codex では文字列のまま残る。

#### ローカル限定の内容

個人の環境、資格情報の所在、検証用の URL、個人的な作業の好みは、共有する指示ファイルへ記述しない。

配置場所は、リポジトリ内のローカル専用ファイルを既定とする。ルートに 1 つ配置して gitignore に追加し、`AGENTS.md` から参照する。対象のリポジトリで作業するときのみ読み込まれ、設定内容の所在がリポジトリ内で完結する。

ユーザー層（`~/.claude/`、`~/.codex/` など）へ配置する案は、その層を生成元リポジトリから配布している場合には採用しない。生成物を直接編集することになり、次回の生成で失われるためである。個人設定をユーザー層へ配置する必要が生じた場合は、生成元リポジトリの入力を変更する。

ローカル専用ファイルを参照する場合、2 つの制約を伴う。共有する `AGENTS.md` に参照を記述すると、そのファイルが配置されていない環境では参照先が存在しない状態となる。また Codex は参照を展開しないため、内容が適用されるのは Claude Code に限られる。双方のエージェントへ個人設定を適用する必要がある場合は、各ツールが独自に探索するファイル名（Claude Code の `CLAUDE.local.md` など）を用いる。

`AGENTS.override.md` は用いない。Codex は各ディレクトリで `AGENTS.override.md`、`AGENTS.md` の順に探索し、最初に見つかった 1 つのみを読み込む。同一階層に両方を配置すると共有側の `AGENTS.md` が読み込まれなくなる。`CLAUDE.local.md` は後から連結されるため挙動が異なり、同様の配置を行うと共有ルールが失われる。

#### バージョン管理の方針

共有用の指示ファイルはコミット対象とし、個人用のファイルは追跡対象外とする。外部からの pull request を受け入れるリポジトリでは、指示ファイルへの変更を通常のコードと同様にレビュー対象として扱う。指示ファイルに記述された内容はエージェントの動作を変更するため、レビューを経ていない変更は取り込まない。

### 記述の設計

#### 記載内容の取捨

各行について「この記述を消すと、エージェントが誤った操作をするか」を問い、否なら書かない。

記述の対象は、リポジトリ固有であり、コードを読んでも判明しない事実に限る。非標準のビルド・テスト・lint コマンド、言語の既定と異なるコーディング規約、テストの特有の挙動、ブランチと PR の運用ルール、必要な環境変数、非自明な制約が該当する。

記述しない対象は、ファイルやコンポーネントの列挙、言語の標準的な慣習、一般的な開発上の助言、マニフェストファイルから自明なコマンドである。分量の多い参考情報や更新頻度の高い情報は、指示ファイルへ転記せず、参照の記法を用いて対象ファイルを指定する。

#### 分量の制約

指示ファイルはセッションごとにコンテキストを消費する。加えて、読み込みの仕様がツールごとに異なる。

- Codex: ルートから作業ディレクトリへ向かって連結し、累積サイズが `project_doc_max_bytes`（既定 32 KiB）に達した時点で以降を読み込まない
- Claude Code: 上位ディレクトリから連結し、同一階層の `CLAUDE.local.md` を後から追加する

いずれの読み込み方式でも意図した内容が反映されるよう、全エージェントに共通して必要な内容のみを記載し、簡潔に保つ。

#### ツール固有の記述

ツール固有の記述は含めないことを既定とする。必要な場合に限り、Codex および Antigravity に関する内容を `AGENTS.md` へ、Claude Code に関する内容を `CLAUDE.md` の `@AGENTS.md` より下に記述する。

## 完了確認

- 未置換の placeholder と一時ファイルが残っていないこと
- 設定ファイルの参照 path と実際の配置が一致すること
- `.gitattributes` と formatter の改行規則が矛盾しないこと
- 導入したコマンド、hook、CI が対象プロジェクトの依存関係と一致すること
- diff に依頼範囲外の変更や秘密情報が含まれていないこと
- エージェント指示ファイルを扱った場合、正本が `AGENTS.md` の 1 つに定まり、個人用の内容が共有対象へ混入していないこと

新規プロジェクトでは実施内容と検証結果を報告する。既存プロジェクトでは、未承認の提案を実施済みの変更と区別して報告する。
