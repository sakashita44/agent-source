# Independent Review

作成者本人が見落とす欠陥を、経緯を持たない相手に検出させる。委譲の作法は `subagent` を参照する。

同じ成果物を複数の相手へ独立に提供し、結果を統合する。互いの指摘は見せない。提示すると、先に出た指摘に偏った意見しか得られなくなる。

## 実行条件

ユーザーが明示的に依頼した場合に限り実行する。

## 事前検査

同じ入力から同じ結果が得られる検査を、複数の相手へ実行させても新しい情報は得られず、待ち時間と出力量が増加するにとどまる。

依頼の前に自身で実行し、結果を記録する。

- テスト、リンタ、型検査、ビルド
- リポジトリ固有の検証スクリプト
- 変更した成果物に対応する機械検査

出力はファイルへ保存し、依頼資料からその配置場所を指定する。合否だけでなく、指摘の件数と、指摘を採用しなかった場合の判断理由も記載する。検出器による誤検出は誤検出であると明示する。記載しないと、レビュワが同じ指摘を再提出することになる。

検査が失敗した状態で依頼しない。事前に修正するか、修正しない理由を資料へ記載する。

## 依頼資料

一つのファイルにまとめ、レビュワには最初にこれを読ませる。次の内容を含める。

- 対象: ブランチ、比較元、変更の規模、差分の取得方法
- 成果物が何であり、どこへ配布または適用されるか
- 実施済みの検査: コマンド、結果、ログの配置場所、再実行を抑止する指示
- 未実施の項目: レビュワが実施してよい項目として明示する
- レビューの観点: 対象とする観点と、対象外とする観点
- 出力の形式と件数の上限
- 承認要求や着手宣言だけで終わらせず、結果本体を出力する指示

2 巡目以降は、次の項目も追加する。

- 前回の指摘のうち修正済みの項目: 再指摘を禁止し、修正が不十分な場合に限り指摘させる
- 前回の指摘のうち事実として誤っていた項目: 同様の主張の再発を抑止する
- 自身が作成した記録に誤りがあった場合に、その記録を根拠にする前に実物と照合する指示

## 委譲先

ユーザーが指定した相手を用いる。指定がない場合は、どの相手へ依頼するかを確認する。相手の数、製品、モデルを独断で決定しない。

各相手へ同じ資料を提供し、独立して実行させる。実行中の相手の結果を、他の相手へ提供しない。

対象リポジトリへファイルを作成させない。差分の書き出しや作業メモが必要な場合は、実行環境の一時領域へ配置するよう資料に記載する。依頼後は、対象リポジトリに増えたファイルがないか確認する。

## 統合

レビュワの完了報告をそのまま結論としない。

1. 事実の主張を一次情報で確かめる。リポジトリの実ファイル、ツールの公式文書、実行結果のいずれかを参照する。確かめずに採用しない
2. 誤りを含む指摘は、誤りとして分けて記録する。指摘した相手ではなく、根拠が何と食い違うかを記載する
3. 複数の相手が同じ箇所を挙げた場合は一件へまとめる。挙げた相手の数を、指摘の重みにしない
4. 読み手の判断を変えない指摘を除外する
5. 残った指摘を、修正するもの、判断を要するもの、記録して先送りするものへ分ける

判断を要する事項は、選択肢と、各選択肢を採用した場合の結果を添えてユーザーへ提示する。

ユーザーへは、統合した指摘、誤りだった指摘、判断を求める点を分けて提示する。事前検査で検出して修正した内容も併せて報告する。
