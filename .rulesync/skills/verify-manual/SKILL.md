# verify-manual

ドキュメントの操作的十分性を検証する。低コンテキストな実行者がドキュメントの記述だけでタスクを遂行できるかを、最弱モデルにドキュメント本文のみから実行計画を立てさせ、その計画を実環境に当てて確認する。

強いモデルは事前知識で省略された手順を補完するため、ドキュメントの欠落が表面化しない。最弱モデルは補完力が低く、ドキュメントが明示しない手順・前提・パラメータで詰まる。その詰まりがドキュメントの欠陥を示す。

## 検証対象の決定

- 第1引数: 対象ドキュメント（必須、glob パターン可）。手順を記述した README やセットアップガイドなど
- 第2引数以降: 達成ゴール（任意）。省略時はドキュメントが記述する手順自体を遂行対象とする

引数で対象が定まらない場合はエラーとして終了する。

## 計画立案

最弱モデルにドキュメント本文のみを根拠とした実行計画を作らせる。

1. オーケストレータが対象ドキュメントを Read で読み込む
2. `Agent` で指定可能なモデルのうち最も能力の低いものを選び、そのモデルで計画エージェントを起動する。ドキュメント本文はプロンプト内に inline で渡す
3. 計画エージェントへの指示:
   - 渡されたドキュメント本文だけを根拠に、ゴール達成までの手順を分解した実行計画を作る
   - 判断はドキュメント本文のみで行う。リポジトリやコードは参照しない
   - 追加で必要な情報は、手元の記述が名前またはパスで明示的に指す別ドキュメントに限り、オーケストレータに取得を要求できる。明示的な指し示しがないまま必要になった情報は、詰まりログに欠落として記録する
   - 各ステップで実行する具体的なコマンド・操作を明記する
   - 推測・補完で埋めた箇所、複数解釈が生じた箇所、情報欠落で手が止まった箇所を詰まりログに記録する

要求された明示参照先ドキュメントは、オーケストレータが Read で取得して計画エージェントに渡す。

計画エージェントの出力:

- 番号付きの実行計画（各ステップの具体的コマンド/操作）
- 詰まりログ（推測・曖昧・欠落と、対応するステップ）

## 実行と照合

計画を実環境（作業ディレクトリ）に当てる。各ステップを副作用の有無で分類する:

- 安全なステップ: 純粋な読み取り、`--help`/バージョン確認、プロジェクトローカル環境への依存インストール、lint、ビルド、テスト実行など、副作用が作業ディレクトリ内に限定され可逆なもの
- 破壊的・外部影響のあるステップ: 削除、リモートへの push/commit、デプロイ、公開、外部リクエスト送信、作業ディレクトリ外への変更、グローバル状態の変更など

実行するコマンドの一覧と、静的照合に留めるステップを提示し、ユーザの許可を得る。許可を得たコマンドのみ実行する。破壊的・外部影響のあるステップは実行せず、参照するファイル/コマンド/フラグ/手順が実在し整合するかを照合する。

各ステップについて記録する:

- 成功 / 失敗（失敗時はエラー出力）
- ドキュメントにない推測が必要だったか
- 参照先（ファイル/コマンド/フラグ）が実在したか

## 欠陥の抽出

実行結果と詰まりログを突き合わせ、各事象を切り分ける:

- ドキュメント欠陥: 記述の不足・曖昧・誤りにより低コンテキストな実行者が詰まる/誤る箇所。本スキルの報告対象
- 環境起因: ドキュメントは十分で、実環境側の問題（依存欠落、設定差異など）で失敗した箇所

詰まりログを主たる根拠とし、実行失敗で裏付ける。

## 出力形式

```
## verify-manual 結果

### 対象
- ドキュメント: <ファイル>
- ゴール: <ゴール、またはドキュメント記述の手順>

### ドキュメント欠陥
- [該当ステップ] 欠陥の内容（推測/曖昧/欠落/誤り）と、不足している記述
  - 補うべき記述の提案

### 環境起因
- [該当ステップ] 環境側の事象

### 総合: PASS / FAIL（N 件のドキュメント欠陥）
```

ドキュメント欠陥がない場合は「PASS: ドキュメントのみでゴールを遂行可能」と報告する。
