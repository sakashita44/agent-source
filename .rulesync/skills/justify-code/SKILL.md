# Justify Code

既存のコードについて、現時点で存在を正当化できるかを問う。静的解析とコードレビューは、書かれたコードの内部を見る。この Skill は、そのコードを書く必要があったかを外から問う。

判定には、コードの外にある要求が必要となる。ある抽象化が現在の仕様で必要なのか、将来を見越した先回りなのかは、要求を参照しないと決まらない。

削除は行わない。候補と根拠を報告し、判断と実行は利用者に委ねる。

## 実行条件

ユーザーが明示的に依頼した場合にのみ使用する。実装やレビューの流れで自発的に起動しない。

## 問う範囲

`engineering-principles` の判断ラダーのうち、機械検査では判定できない上位の段に絞る。

1. 作る必要があったか。確認された要求で必要性を説明できるか
2. このコードベースに既にあるものと重複していないか
3. 標準ライブラリ、プラットフォームの機能、既に導入している依存で足りないか

下位の段（実装の簡潔さ、命名、型付け、重複の除去）は、静的解析とコードレビューが扱う。ここでは判定しない。

## 入力

- 対象範囲。ファイル、ディレクトリ、または差分。利用者の指示に従う
- 対象が満たすべき要求。仕様書、Issue、README、設計文書など、参照できるものをすべて渡す

要求を特定できない場合は、その事実を報告する。要求の不在は、この Skill が検出する対象の一つである。要求を推測して、それに照らした判定を行わない。

既存コードは複数の要求の蓄積で成立している。対象範囲に対応する要求を網羅できていない状態で、要求にないという理由だけで不要と判定しない。

## 手順

1. 対象範囲と、参照できる要求を確定する
2. 対象を読み、要素ごとに、どの要求に対応するかを対応付ける
3. 対応する要求を特定できなかった要素を挙げる
4. 各要素について、コードベース内の既存実装、標準ライブラリ、プラットフォームの機能、既存の依存で置き換えられるかを確認する
5. 候補を、根拠と影響範囲とともに報告する

## 報告

- 要求に対応付けられなかった要素と、その根拠
- 既存実装、標準ライブラリ、既存依存で置き換えられる要素と、置き換え先
- 対応する要求を特定できなかったが、判断材料が不足している要素
- 参照できなかった要求と、それが判定へ与える限界

削除または置き換えを実行しない。利用者が判断できる形で候補を示す。
