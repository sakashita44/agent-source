# implement

実装作業をオーケストレータとして進める。メインコンテキストは計画・レビュー・統合を担い、一括実行はサブエージェントに委譲する。ファイル単位の詳細と試行錯誤をサブエージェント側に押し出し、メインコンテキストをタスク全体が見渡せる軽さに保つ。

## 適用境界

- 委譲する: 複数ファイルの一括編集、定型的なリライト・移植、テストの追加・修正、失敗と修正を繰り返す作業ループ
- 委譲しない（スキル外でそのまま実行）: 1〜2 ファイルの一発修正、設計判断そのもの、ユーザとの合意形成

## 手順

1. 計画: タスクを自己完結した作業単位に分解する。非自明な設計判断を含む場合、委譲を始める前にユーザ承認を得る（General Workflow の trivial / non-trivial 区分に従う）
2. 委譲: 各作業単位を Agent ツール（subagent_type: general-purpose）で実行する
    - model: 標準は `sonnet`。機械的な置換・整形・定型移植は `haiku`
    - プロンプトは自己完結させる: 対象ファイルパス、期待する結果、従うべき規約（プロジェクト CLAUDE.md の該当ルール、命名規則、除外パス等）をプロンプト内に明示的に再掲する。サブエージェントは会話の文脈を持たない前提で書く
    - プロンプトに「Skill ツール・Agent ツールは使用しないこと（さらなる委譲・再帰的なスキル呼び出しを禁止）。直接ツール（Read/Edit/Write/Bash 等）のみでこの作業単位を完結させること」を明記する
    - 独立した作業単位は並列で出す
3. 統合: サブエージェントの報告を鵜呑みにせず、変更されたファイルの diff を確認する。基準に満たなければ修正指示を出すか、仕上げのみメインで行う
4. 報告: 何を委譲し、どう検証・統合したかをユーザに報告する

## 制約

- 設計判断・アーキテクチャ選択はサブエージェントに委ねない。判断済みの内容を実行させる
- コミットは行わない。コミットはユーザの指示を受けて commit スキルで行う
- サブエージェントへの委譲は1階層まで。作業単位の分割が粗すぎて追加の分解が必要になった場合、サブエージェント自身に再委譲させず、メインが結果を見た上で作業単位を分割し直して追加でスポーンする
