# Add Comment

コメントの執筆を、実装していないエージェントへ委譲し、返ってきた結果を確認する。

コメントの是非は、実装の記憶を持たない立場でしか判定できない。実装した本人、または実装を指示したオーケストレータがこの手順を自分で実行しても、判定の前提が成立しない。このSkillの本体は委譲であり、自分でコメントを書かない。

委譲の作法は`subagent`に従う。

## 手順

1. 対象の範囲を確定する。差分を対象とする場合は変更したファイルと範囲を、既存コードを対象とする場合は対象のファイルまたはディレクトリを定める
2. 委譲前の状態を記録する。対象ファイルの内容そのものをAI側の一時領域へ控える。`git diff`だけでは、未追跡ファイルの中身が出ず、未コミットの変更と同じ位置へコメントが入った場合に切り分けられない
3. `write-comments`サブエージェントを起動する。渡すのは次に限る
    - 対象の範囲。ファイルのパスと、差分であればその範囲
    - コメントの理由を特定するために参照してよい情報源。関連するIssue、外部仕様のURLなど
4. 実装中に検討した内容、採用しなかった案、なぜその実装にしたかを渡さない。渡すと、委譲先が実装者と同じ視点になり、独立した判定にならない
5. 委譲後の対象ファイルを、控えておいた内容と突き合わせる。増えた分が委譲先の変更である。コミットを挟む必要はない
6. 対象範囲の外への変更、動作の変更、実装の言い換えになっているコメントがあれば、差し戻すか自分で取り消す
7. 置かれたマーカーのうち、実装者として理由を答えられるものを補う

## 確認する内容

- 追加されたコメントが、コードの外側にある事情を説明しているか
- 対象範囲の外を編集していないか
- コードの動作が変わっていないか
- 既存のコメントが削除されていないか

## 報告

委譲した範囲、追加されたコメント、残ったマーカー、削除を提案された既存コメント、設計で解消すべきと報告された箇所を示す。マーカーが残っている場合は、誰が補うかを明示する。
