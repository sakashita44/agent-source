# 内容種別ごとの規則

README、手順、コード例、Reference、設計・アーキテクチャ文書を書くときに、該当する節を適用する。

## README

- ツール: 利用者を主な読者とし、概要、インストール、設定、基本的な利用方法、問題発生時の参照先を順に置く。内部構造は、導入や運用の判断に必要な概要だけを置く
- フレームワーク: 導入者と設計者を主な読者とし、適用範囲、利用上の制約、設計意図、推奨する使い方、拡張時の判断基準を置く
- 実装例: 実例を理解・再現する読者を主な読者とし、構成、採用した設計、その理由、実行方法を置く。一般的な設計規則は、その規則が必要になる条件とともに正本へ案内する

トップレベルの README は、リポジトリを初めて扱う読者が、目的に応じて次に読む場所と取る行動を判断できる入口を担う。

## 手順

読者が安全に開始し、完了を確認し、失敗から回復できる情報を置く。

- 開始条件: 対象環境、権限、必要物、前提作業、初期状態を示す
- 実行: 読者が行う操作を順に置き、各操作の対象と判断条件を明示する
- 完了条件: 期待する結果と、その結果を確認する方法を示す
- 回復: 失敗の識別方法、安全な再試行、元へ戻す方法、診断先のうち該当する情報を示す。回復手段がない場合は、その制約を操作前に示す

通常の動作説明を手順として書く場合も、読者が操作する範囲とシステムが自動実行する範囲を区別する。

## コード例

コード例は、目的を検証でき、安全に試せ、想定読者が利用できる形にする。

- 目的: 例が示す利用方法または結果を明記する
- 前提: 言語、ランタイム、依存関係、認証、入力、実行場所のうち必要な条件を示す
- 検証可能性: 実行コマンド、期待結果、確認方法を示す。省略記号や未定義名を含む断片を実行可能な例と称しない
- 安全性: 破壊的操作、課金、外部送信、資格情報、実環境への影響を操作前に示し、安全な入力または隔離環境を用いる
- アクセシビリティ: 色、位置、画像だけへ意味を持たせず、コード、出力、操作対象をテキストで識別する。画像内のコードだけを唯一の例にしない
- 区別: 説明用の断片、実行可能な例、出力をラベルで区別する

擬似コードは、ツール、API、DSL、フレームワークなどの利用者が利用方法を理解する例に限って用いる。利用者が実行できない場合は、擬似コードであることと実コードとの差を明示する。

## Reference

Reference は、読者が既知の識別子または対象から仕様を検索するための公開構造を担う。

- 検索軸: コマンド、API、設定項目、型、イベントなど、読者が検索する公開識別子または対象を軸に並べる
- 項目名: 目次、検索結果、リンク先から単独で識別できる公開名を用いる
- 共通構造: 対等な項目に、意味、形式、制約、既定値、例、関連項目のうち該当する情報を同じ順序で置く
- 完全性: 公開対象を漏れなく記録する。未公開の内部要素を公開項目と同列に置かない
- 導線: 概念理解や一連の操作が必要な読者を、条件とともに概念文書または手順へ案内する

Reference をチュートリアルの実行順や実装内部の配置順で構成しない。

## 設計・アーキテクチャ文書

設計・アーキテクチャ文書には、責務、境界、依存関係、データまたは制御の流れ、制約、採用した設計、その理由を置く。

実装の型、関数、分岐、処理順を擬似コードで模写しない。模写は実装と別に更新される第二の実装となり、正本を分散させる。具体的な実装を確認する必要がある場合は、対象となる実コードを条件とともに参照する。概念間の関係は、文章、表、図で表す。

再利用される仕組みの設計文書には、利用上の制約、設計意図、推奨する使い方、拡張時の判断基準を記す。具体的な実装の文書には、構成、採用した設計、その理由、運用方法を記す。
