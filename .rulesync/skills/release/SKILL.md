# Release

CHANGELOG の `[Unreleased]` をバージョン見出しへ昇格し、タグを作成する。

Git 操作の共通原則は `git-general`、コミットの作成は `commit` に従う。

## 実行条件

ユーザーが明示的にリリースを依頼した場合にのみ使用する。

対象リポジトリに独自のリリース手順がある場合は、それを優先する。`AGENTS.md`、`CLAUDE.md`、トップレベルの `README` を事前に確認し、その他はリリース関連の設定ファイルを探索して特定する。特定のファイル名の列挙に依存しない。

対象リポジトリにリリースの自動化機能がある場合は、その仕組みを実行経路として利用し、この Skill の手順で置き換えない。

## 開始前の確認

- デフォルトブランチにいること
- 作業ツリーがクリーンであること
- リモートと同期していること
- GitHub Release 運用の有無を確認していること
- CHANGELOG の `[Unreleased]` が空でないこと（空の場合は昇格を行わずに終了する）

## バージョンの判定

引数でバージョンが指定されていない場合は、`[Unreleased]` の内容から SemVer を判定する。破壊的変更の有無は、エントリの本文から読み取る。

バージョンが指定されている場合でも、そのまま採用せずに次の点を確認する。1つでも適合しない項目がある場合は、指定された版と判定した版の差異を提示して確認を求める。

- 既存タグの最新版から連続しているか（番号の欠落や降順になっていないか）
- `[Unreleased]` の内容とバージョンの増分が対応しているか（破壊的変更があるにもかかわらず patch になっていたり、機能追加のみであるにもかかわらず major になっていたりしないか）
- 既存タグの命名慣行と形式が一致しているか

既存タグ、CHANGELOG の見出し、バージョン番号が記載されたファイルの間で不整合がある場合は、昇格を行う前に報告する。

判定結果と根拠をユーザーへ提示し、確認を得てから次へ進む。

## 昇格とタグ

1. `[Unreleased]` をバージョン見出しへ昇格して日付を付与し、新しい空の `[Unreleased]` 節を設ける
2. 比較リンクを持つ CHANGELOG では、リンクを更新する
3. バージョン番号が記載されたファイルを探索して更新する。整合性の確認は、対象リポジトリに検証の仕組みがあればそれを利用する
4. `commit` を使ってリリースコミットを作成する
5. 既存タグの命名慣行に合わせてタグを作成する
6. タグを含む push は、実行前にユーザーへ確認する
7. GitHub Release の運用がある場合は、CHANGELOG の該当節を notes として Release を作成する

デフォルトブランチ上で昇格コミットとタグを作成する。リリース専用ブランチは作成しない。昇格コミットは機械的な変更であり、レビューの対象としない。

## 報告

昇格したバージョン、更新したファイル、タグ、Release URL を報告する。
