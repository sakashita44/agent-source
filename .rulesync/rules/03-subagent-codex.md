## Codex から agy へ委譲する場合

Windows でコマンド名 `agy` の解決に失敗しても、それだけで `agy` を未導入と判断しない。Codex の sandbox は `PATH` 上のディレクトリの列挙を制限し、コマンド名による解決だけを失敗させる場合がある。名前解決に失敗した場合は、プロセスの `PATH` に含まれる各ディレクトリへ `agy.exe` を連結した候補パスを `PATH` の順に組み立て、ファイルの存在を確認できた最初の候補を絶対パスで起動する。候補の確認にはディレクトリの列挙を用いず、組み立てたパスごとに存在を確認する。どの候補も確認できない場合に限り、ユーザーへ `agy.exe` の絶対パスを確認する。名前解決のために sandbox の権限追加や環境設定の変更を行わない。

読み取り専用の調査を `agy` へ委譲するときは、送信先が Google Antigravity であること、対象 path、読み取り専用であることを委譲プロンプトと実行時の説明へ明記する。ユーザーまたはプロジェクトの指示が `agy` への読み取り委譲を許可している範囲では、同じ許可を重ねて確認しない。許可された path を超える場合、秘密情報を含む可能性がある場合、または編集や外部状態の変更が必要な場合は、実行前に確認する。

Web 調査では、headless mode が `read_url` の許可を要求し、確認できないまま自動拒否する場合がある。出力に `read_url permission` または `auto-denied` が現れた場合は調査結果なしとして扱い、権限拒否を原因として報告する。

`--dangerously-skip-permissions` は `read_url` だけでなく全 tool の権限確認を省略するため、読み取り専用指定と同義ではない。外部で隔離された環境と明示的な許可がある場合だけ使用する。特定 tool だけを許可できる設定が利用可能なら、その限定設定を優先する。
