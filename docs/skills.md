# Skill の一覧

`agent-source` が配布する Skill を、役割と用途ごとにまとめた要約一覧である。詳細な起動条件と手順は、各 Skill の `.rulesync/skills/<Skill 名>/SKILL.md`（外部リポジトリから取得した Skill は `.rulesync/skills/.curated/<Skill 名>/SKILL.md`）に定められている。実行基盤や事前準備が必要な Skill については、[README.md の「要求環境」](../README.md#要求環境)を参照のこと。

## 起動方法

- 自動: エージェントが依頼内容から判断して読み込む。利用者が名前を指定して手動で起動してもよい
- 手動: 利用者が名前を指定した場合のみ起動される。エージェントは Skill を自動では起動しない

名前を指定して起動する場合は、Claude Code と Antigravity（IDE・CLI）では `/<Skill 名>`、Codex では `$<Skill 名>` と入力する。

## 判断の原則

設計、文章、検証、Git 操作、実行環境の障害などの場面で、エージェントが判断の基準として自動で読み込む。

| Skill | 用途 | 起動 |
| --- | --- | --- |
| `engineering-principles` | 設計、実装、レビュー、技術的な提案で、解決の範囲、採用する手段、既存の構造との整合を判断する | 自動 |
| `artifact-principles` | 情報と意図を、コード、テスト、コメント、Issue、文書、ADR のどこに配置するかを判断する | 自動 |
| `writing-principles` | 文書、Issue、PR description、コメント、コミットメッセージなど記録として残る文章と、UI 文言を執筆、修正、レビューする | 自動 |
| `verification-principles` | テストを設計し、検証方法を選択し、根拠を評価して作業の完了を判定する | 自動 |
| `git-general` | Git の状態や履歴を参照し、ブランチ、コミット、PR、リリースに関わる操作を実行または提案する | 自動 |
| `subagent` | サブエージェントへ作業を委譲する際に、委譲先、依頼文、結果の検証方法を決定する | 自動 |
| `stack-conventions` | 特定のプラットフォームを対象に開発する際に、UI ツールキット、言語、バージョンなどの技術構成を選択する | 自動 |
| `known-runtime-issues` | 実行基盤やサンドボックスが原因とみられる失敗を、既知の事例と照合して対応を決定する | 自動 |

## 作業別の Skill

### 開発工程

| Skill | 用途 | 起動 |
| --- | --- | --- |
| `grill-me` | 要件、範囲、成功基準が定まっていないときに、質問を重ねて要件を確定する | 手動 |
| `plan` | 機能やマイルストーンを計画し、ロードマップを作成して作業を Issue に分解する | 自動 |
| `implement` | 方針が決まった実装を開始する。実装中はコメントを記述せず、完了後に `add-comment` を実行する | 自動 |
| `add-comment` | 実装に関わっていないエージェントにコメント内容を提案させ、その内容を反映する | 自動 |
| `justify-code` | 既存コードのうち、現行の要件から必要性を説明できない部分や、標準ライブラリまたは既存の依存パッケージで置き換えられる部分を報告する | 手動 |
| `independent-review` | 経緯を共有しない別のエージェントに変更をレビューさせ、結果を統合する | 手動 |
| `setup-project` | リポジトリの開発標準を整備するか、導入すべき基本設定を評価する | 自動 |

### 文書

| Skill | 用途 | 起動 |
| --- | --- | --- |
| `write-docs` | 技術文書、README、ADR、PR description を執筆し、機械検査まで実行する | 自動 |
| `refine-docs` | 書き上げた日本語の文書を推敲し、修正前後の対比と元に戻す候補を報告する | 自動 |
| `verify-docs` | 技術文書が執筆規則に従っているかを検証する | 手動 |
| `verify-manual` | 手順書の本文のみで作業を遂行できるかを検証するため、別のエージェントに実行計画を作成させて実環境と照合する | 手動 |
| `natural-japanese` | 日本語の文章を自然で読みやすく修正し、AI らしさを診断する（外部リポジトリ `coji/natural-japanese` から取得。取得手順は [README.md の「初回セットアップ」](../README.md#初回セットアップ)を参照のこと） | 自動 |

### Git 操作

| Skill | 用途 | 起動 |
| --- | --- | --- |
| `commit` | 変更の単位を確定し、Conventional Commits の形式でコミットする | 自動 |
| `pr-merge` | CI、レビュー、CHANGELOG を確認して PR をマージし、ブランチを整理する | 自動 |
| `release` | CHANGELOG の Unreleased をリリースバージョンへ昇格し、タグを作成する。GitHub Release の運用がある場合は、GitHub Release も作成する | 自動 |

### 調査・外部サービス連携

| Skill | 用途 | 起動 |
| --- | --- | --- |
| `deep-research` | 複数の情報源を参照する調査や比較を、計画の承認を経て実施し、出典付きのレポートにまとめる | 自動 |
| `google-web-analytics` | Web サイトやブログの Google Analytics 4 と Search Console のデータを、利用者の認証情報を用いて API から取得する | 自動 |
| `bitwarden-vault` | Bitwarden の保管庫の秘密値をエージェントに見せずに、GitHub Actions の secret 登録、SSH 経由の sudo 認証、任意コマンドへの受け渡し、新しい秘密値の生成と保存を実行する。項目やフォルダの棚卸しと編集、秘密値の一致照合にも対応する。秘密値を含みうる操作や保管庫の変更は、利用者が承認ウィンドウで許可してから実行される | 自動 |
| `notion-workspace` | Notion MCP を用いて利用者の Notion ワークスペースを操作する。Notion 側に配置された運用規則 DB から規則を取得し、それに従って操作することを前提とする | 自動 |
